# Game Art Sourcing Visual System Stack

## 使用边界

Visual System Stack 用于把零散画面观察组织成项目级视觉系统。只有以下请求需要完整读取本文件：

- 完整美术分析。
- 系统性视觉研究。
- 当前项目借鉴。
- Art Bible 规则提炼。
- 生产可行性分析。

简单素材请求不要求完整读取本文件；只交付可靠来源、素材用途和必要的视觉摘要。单点问题只展开与请求直接相关、且有证据支撑的层，不为填满框架而补写无关内容。缺少证据的相关层或观察项明确写 gap。

五层之间形成一条传递链：

```text
视觉身份定义识别规则
→ 资产系统把规则做成内容
→ 体验系统让规则在游玩中被感知
→ 品牌系统把规则压缩成对外承诺
→ 生产系统保证规则可实现、可扩展、可持续一致
```

## 横向判断契约

每个被展开的层都必须回答以下三个问题，并把答案绑定到图片、视频时间戳或明确来源：

1. **玩家情绪**：这一层希望玩家感到什么；情绪来自哪些可观察的视觉手段。
2. **功能可读性**：这一层承担什么玩法、信息、层级或品牌识别功能；玩家能否快速读懂。
3. **进程或状态变化**：这一层如何随游戏进度、角色/建筑/世界状态、时间天气、战斗阶段、交互反馈或镜头变化而变化。

不要用“氛围很好”“很有辨识度”代替回答。区分画面事实、方向性判断和待验证推测；单帧不能证明动态规律或具体实现技术。

## 1. 视觉身份

视觉身份定义项目最基础、跨资产复用的画面语法。它回答“为什么不同内容仍然像同一个游戏”。

### 观察项

- **形体**：基本几何、轮廓节奏、比例、夸张部位、软硬与曲直关系、负形、重复母题。
- **色彩**：主辅点缀色、冷暖关系、饱和度和明度区间、阵营/稀有度/危险度编码、场景与角色分离方式。
- **材质**：写实或风格化程度、粗糙度与反射层级、表面细节密度、磨损语言、材质对比、手绘或程序化痕迹。
- **光照**：主辅光关系、明暗组织、轮廓光、局部强调、环境光色、时间天气差异、角色与交互物可见性。
- **构图**：主体位置、视觉动线、前中后景、留白、焦点层级、镜头距离与地平线、画面信息密度。

### 展开时必须回答

- **玩家情绪**：形体、色彩、材质、光照和构图共同承诺的是力量、温暖、危险、荒诞、秩序、神秘，还是其他明确感受？
- **功能可读性**：核心主体、敌我、危险、资源、交互入口和视觉层级如何被快速区分？识别是否跨远景、近景和不同背景成立？
- **进程或状态变化**：视觉身份中的哪些规则保持稳定，哪些变量会随成长、损坏、昼夜、天气、区域、阵营或战斗阶段变化？

## 2. 资产系统

资产系统检查视觉身份如何落到可生产、可组合、可扩展的内容族群，而不是只看少量明星资产。

### 观察项

- **角色**：体型谱系、剪影、面部与动作可读性、服装分层、职业/阵营/等级差异、换装与成长空间。
- **环境**：地貌、植被、天空和气氛、路径引导、地标、前中后景组织、区域差异与模块复用。
- **建筑**：功能轮廓、体量层级、入口和朝向、升级阶段、损坏/占领状态、模块化套件、与角色尺度关系。
- **道具**：交互距离下的识别、用途形状、持有/摆放尺度、稀有度与状态编码、资产复用和变体策略。
- **生物**：物种轮廓、运动方式、生态位置、威胁等级、群体密度、受击/死亡/驯化或成长状态。

### 展开时必须回答

- **玩家情绪**：不同资产族群分别强化什么情绪，它们如何共同构成可信、向往、压迫或可占有的世界？
- **功能可读性**：玩家能否从轮廓、尺度、色彩、动作和摆放关系读出角色职责、建筑功能、道具用途、生物威胁与环境路径？
- **进程或状态变化**：角色、环境、建筑、道具和生物如何表现升级、损坏、占领、资源丰枯、区域推进、生态变化或阵营转换？

## 3. 体验系统

体验系统检查视觉规则如何进入实时游玩、反馈和叙事，而不是停留在静态截图。

### 观察项

- **镜头**：默认距离、视角高度、视野、跟随与锁定、构图重心、战斗/探索/建造/叙事镜头切换。
- **动画**：姿态、速度曲线、起手与收招、停顿、重量、夸张幅度、循环节奏、交互和受击反馈。
- **战斗可读性**：敌我识别、攻击预警、范围边界、命中反馈、遮挡控制、信息优先级、多人或群体战斗密度。
- **VFX**：形状语言、色彩编码、粒子和拖尾、屏幕覆盖、持续时间、技能层级、环境与角色特效的分离。
- **UI**：信息架构、字体、图标、边框和材质、状态颜色、屏幕位置、世界 UI 与 HUD 的关系、输入与反馈状态。
- **叙事演出**：角色站位、表情与动作、剪辑、景别、灯光和色彩变化、场景调度、可交互与非交互段落衔接。

### 展开时必须回答

- **玩家情绪**：镜头、动画、VFX、UI 和演出如何塑造节奏、冲击、控制感、紧张、放松或叙事亲密度？
- **功能可读性**：玩家是否能在目标镜头和真实信息密度下读出行动机会、威胁、命中、技能层级、资源状态与下一步操作？
- **进程或状态变化**：视觉反馈如何覆盖进入、蓄力、命中、持续、结束、冷却等阶段，以及探索、战斗、建造、剧情和失败/胜利状态之间的转换？

## 4. 品牌系统

品牌系统检查游戏内视觉身份能否被压缩成商店与营销场景中的稳定承诺，并避免营销画面与实际体验脱节。

### 观察项

- **Logo**：字形、图形符号、横竖版和小尺寸识别、明暗背景适配、与世界观及品类的关系。
- **Key Art**：主角与核心冲突、构图层级、色彩焦点、世界尺度、情绪承诺、与实际角色/场景规则的一致性。
- **商店图**：首屏卖点、截图顺序、玩法与美术信息密度、文字覆盖、设备画幅、不同市场的本地化适配。
- **UA/营销素材**：前三秒钩子、镜头和字幕节奏、可识别资产、玩法真实性、变体模板、不同受众与渠道的画面策略。

### 展开时必须回答

- **玩家情绪**：Logo、Key Art、商店图和 UA 首先许诺什么体验情绪，进入游戏后是否兑现？
- **功能可读性**：在缩略图、短停留和静音观看条件下，玩家能否认出游戏、品类、核心角色、核心行为和差异化卖点？
- **进程或状态变化**：品牌素材如何覆盖认知、兴趣、转化和回流阶段，以及新版本、赛季、活动、地区与受众变化，而不丢失核心识别？

## 5. 生产系统

生产系统检查视觉规则能否在目标团队、预算、周期和设备上稳定实现。只凭成片无法确认的管线结论必须标为推测或待验证。

### 观察项

- **Shader**：材质模型、风格化光照、描边、透明和特效、变体数量、平台兼容、作者可调参数与维护成本。
- **Technical Art**：资产规范、LOD、烘焙、灯光、程序化工具、VFX 管线、自动校验、引擎集成和问题诊断。
- **性能**：面数、贴图和材质预算、Draw Call、Overdraw、骨骼与动画、粒子、灯光、后处理、内存和加载压力。
- **设备档位**：目标设备、画质档、分辨率和帧率、特效/阴影/后处理降级、UI 安全区、热量与功耗约束。
- **外包**：资产包定义、输入参考、验收标准、里程碑、返修边界、源文件和命名规范、跨供应商一致性。
- **一致性治理**：Art Bible、golden sample、评审节点、例外审批、版本管理、自动检查、回归抽查和规则维护责任人。

### 展开时必须回答

- **玩家情绪**：在降档、批量生产和外包扩充后，哪些视觉信号必须保住，才能维持核心情绪承诺？
- **功能可读性**：性能优化、设备降级和资产变体是否会损伤轮廓、色彩编码、战斗反馈、UI 信息或品牌识别？
- **进程或状态变化**：管线如何支持升级、损坏、换装、昼夜天气、赛季活动、内容迭代与版本回归，而不靠逐个资产手工修补？

## 输出检查

完成选中层后检查：

- 每个展开层都有“玩家情绪 / 功能可读性 / 进程或状态变化”三个回答。
- 每个回答都能回指实际画面或明确来源；动态结论优先使用连续帧、真实 gameplay 或多个状态证据。
- 观察项只写有证据的内容；相关但缺失的证据写 gap。
- 五层术语保持一致：品牌承诺能回到游戏内体验，生产规则能保护视觉身份，资产变体能支撑状态变化。
- 输出深度服从用户任务；不把本文件变成所有请求都必须填满的固定模板。
